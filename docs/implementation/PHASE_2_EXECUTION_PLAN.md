## 1. Scope

### In scope (Phases.md)

1. Global identity
2. Internal Team and Customer separation
3. Authentication (within ADR-006 decision)
4. Customer single active session
5. Company and branch management
6. Owner Panel and Branch Panel
7. Membership and branch assignments
8. Branch-specific roles
9. Permission Masters
10. Ownership transfer
11. Deactivation and suspension
12. Dashboards

### Exit criteria (Phases.md)

- Cross-company and cross-branch negative tests
- Owner isolation
- Session revocation
- Immediate permission invalidation

### Explicitly out of scope

- Phase 3 masters, common document service, subscription catalogue, Razorpay
- Broker / OwnFleet / Partload modules
- ADR-010 accounting posting implementation
- Installing packages without PO case-by-case approval (`PO-P1-DEPS` pattern)
- Hard delete / restore APIs
- Public self-registration; self-service email change; self-service account deletion
- Sibling `website/` changes

**P2-WS-4 evidence (22 November 2026):**

- Persistence: `customer_web_sessions` (UUID PK, unique `user_id`, `session_id` fingerprint — not raw session secrets). Laravel session store remains payload authority; registry is the Customer active-session pointer.
- Failure behaviour: Customer validity DB errors / missing registry / mismatched id → fail closed (logout + redirect/401). Cache lock acquisition failure aborts login registration.
- Concurrency: serialized via `Cache::lock` + row `lockForUpdate`. True multi-process HTTP race not load-certified in Pest; lock/replacement unit path covered in `SessionPolicyTest`.
- Tests: `tests/Feature/SessionPolicyTest.php` (Customer replace, failed-login non-revoke, stale logout, Internal/Super Admin multi-session, password change/reset revocation, identity ineligibility, fixation/CSRF/registration negatives). Full suite 214 passed / 2 skipped.

## 5. Testing and security gates

For every implementing workstream:

1. Cross-tenant negative tests for any new HTTP/job/file path
2. Authorization on API, jobs, reports, exports, files — including **Internal Team customer-file denial** and **active-company-only** multi-company file access
3. Audit atomicity for mutations (`AuditedTransaction`)
4. No hard delete/restore
5. Immediate permission/session invalidation where applicable (Laravel **web** sessions)
6. CI: Postgres migrate + Pest, Pint, Larastan, frontend checks

Phase 2 exit suite must explicitly cover Phases.md exit bullets with executed tests — not policy checklists alone.
